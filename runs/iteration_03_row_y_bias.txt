## Single change (T035 follow-up — row-Y bias)

Enable one post-fit correction layer on the active `pca4_baseline` path:
`APPLY_ROW_Y_BIAS = True` (was `False`); `APPLY_LOCAL_Y_CORRECTION` stays `False`
(single lever per iteration).

| Config (`typing_candidate.py`) | Before (Iter 2) | After (Iter 3) |
|--------------------------------|-----------------|----------------|
| `APPLY_ROW_Y_BIAS`             | `False`         | **`True`**     |
| `APPLY_LOCAL_Y_CORRECTION`     | `False`         | `False`        |
| `ALPHA_GRID` / `MIN_ALPHA`     | (Iter 2 grid)   | unchanged      |

Mechanism: after the ridge fit, `compute_row_y_residuals()` measures the mean
`(pred_y − target_y)` over the top / middle / bottom calibration rows and stores
`(row_y_centers, row_y_bias)`. `MapperWithRowBias` then subtracts the nearest-row
bias from predicted **Y only** at predict time. **X is never touched**; mapper
family stays `pca4_baseline` (no new mapper, no local-Y layer, no layout / geometry /
collection / benchmark / smoothing change).

Justification (from prior records): baseline + iterations 1–2 showed a persistent
vertical row-compression / row-error signature (`row` accuracy 40%–53% on every
benchmark run; failure analysis dominated by row misses), motivating a Y-axis row
correction rather than another α sweep.

## Verification — dx/dy & row_y_bias definitions, and data scope (no code changed)

Confirmed directly against source before drawing any dy conclusion:

1. **Benchmark dx/dy** (`gazekey/evaluation/benchmark_runner.py`, `build_result_row`):
   - `dx = predicted_x − target_center_x`
   - `dy = predicted_y − target_center_y`
   - Screen Y increases downward, so `dy > 0` ⇒ prediction landed **below** the target
     key center. These are **post-correction** residuals (the benchmark runs the active
     mapper, which already wraps the row-Y bias when `APPLY_ROW_Y_BIAS=True`) and are
     measured against the **intended target key's** center even when another key was hit.

2. **row_y_bias** (`gazekey/calibration2/region_quality.py`, `compute_row_y_residuals`;
   applied in `gazekey/mapping/row_bias.py`):
   - `bias[row] = mean(predicted_y − target_y)` over that row's **calibration-train** samples
   - `corrected_y = predicted_y − bias[nearest row center]`
   - Same `(predicted − target)` sign convention as benchmark `dy`, so the two are directly
     comparable. The bias is fit on **calibration**, not benchmark.

3. **Data scope — important limitation:** the saved benchmark files record `dx/dy` for
   **failed keys only** (`failure_analysis` writes `per_key_misses = rows where not
   is_correct`). The full 15-target `dx/dy`, the **hits' dy**, and **per-row dy across all
   targets** are produced at runtime (`KeyAccuracyResultRow`) but are **NOT persisted**
   anywhere in `runs/`. From the saved artifacts I therefore **cannot** report mean /
   median / min / max dy over all 15, dy-by-row across all targets, or hits-vs-misses dy.

4. **Scope of the dy-sign statements below:** every dy-sign note is **"dy sign among
   failed keys only."** It is **not** a full-session vertical-bias estimate.

5. **Re-evaluation — overcorrection vs. miss-selection artifact:** the earlier framing
   ("benchmark row residual dy flips sign per session ⇒ the static bias overcorrected") is
   **NOT supported** by the saved data:
   - Misses are selected partly by large **horizontal (dx)** error (e.g. Run 3 misses reach
     dx ≈ −130 px), so the dy sign among misses is **contaminated by X** and is not a clean
     read of vertical bias.
   - **No pre-correction** benchmark residuals are saved, so the post-correction dy sign
     cannot be attributed to the bias layer vs. session posture/collection differences.
   - **Hits' dy is unknown**, so a "uniform session dy direction" cannot be established.
   - What survives the data: **among failed keys only**, Run 1 residuals are all +dy, Run 2
     all −dy, Run 3 mixed. That is a between-session difference **in miss residuals**,
     consistent with session-to-session instability — it does **not** by itself show the
     row-Y bias overcorrected. Confirming/refuting overcorrection requires saving all-15
     pre- and post-correction dy (future instrumentation, not done here).

## Outcome verdict: **PARTIALLY IMPROVED (row accuracy)**; **UNCHANGED (key-hit ceiling, CQ-1 acceptance)**

### Improved
- **Row accuracy** — the metric this lever targets — rose to a post-baseline best of
  **10/15 (67%)** (Run 3) and **9/15 (60%)** (Run 2), versus Iteration 2's best of 53%.
  Two of three runs improved row accuracy vs the prior cycle.
- **Median gate first pass**: Run 2 reached **55 px**, the first post-Phase-8 run to
  satisfy the ≤ 55 px median threshold.
- **X untouched / no family change** verified by `tests/test_row_y_bias_path.py`
  (Y-only correction, active fit wraps `pca4_baseline` with `MapperWithRowBias`,
  local-Y stays disabled, save/load round-trip preserves centers + bias).

### Unchanged / not improved
- **SC-001–SC-003**: 0/3 benchmark runs passed (same as Iteration 2; baseline had 1/3).
- **Best key-hit** stays at **7/15 (47%)** — identical to Iteration 2; baseline Session B
  (10/15, 67%) still not reproduced.
- **Failure cause** remains `likely_cause=mapping` on all three runs; the dominant
  residual driver on the worst-median run (Run 3) is **horizontal (X) error**, which a
  row-Y bias cannot correct.

### Regressed (minor)
- **Key-hit spread widened** to **20 pp** (27%–47%) vs Iteration 2's 7 pp — sits exactly
  at the SC-004 limit. Row-Y bias did not stabilize key-hit; the worst session (Run 1)
  dropped to 4/15 (27%), a new post-baseline low (its misses were all +dy, but see the
  dy-scope caveat — this is not proof the bias was the cause).
- Run 3's median rose to **82 px** despite best row accuracy — row-Y correction can
  pull predictions onto the correct row while leaving large X misses (and even inflating
  total pixel error) untouched.

## Conclusion

T035 follow-up Iteration 3 (enable post-fit **row-Y bias** layer, X untouched, no mapper
family change) **improved the targeted axis** — row accuracy reached a post-baseline best
(10/15, 67%) and median met its gate on one run (55 px) — but **did not raise the key-hit
ceiling** (still 7/15, 47%) or produce a CQ-1 pass (0/3).

Observed limitation: the lever helped **row accuracy** on 2/3 runs but did not lift
key-hit and leaves large **horizontal (X)** misses — the dominant error on the worst-median
run — uncorrected. Among **failed keys only**, miss residual dy differs by session (Run 1
+dy, Run 2 −dy, Run 3 mixed). An earlier draft read this as the bias "overcorrecting / sign
flipping per session"; that is **not supported by the saved data** (misses are partly
X-selected, no pre-correction or all-15 dy is stored — Verification §3–5). Whether the
calibration-train bias transfers to benchmark is **unproven** and should be tested with
all-15 pre/post-correction dy logging before drawing a transfer conclusion.

**Phase 8 checkpoint:** SC-001–SC-003 not met; SC-004 key-hit spread at the 20 pp limit
(degraded vs Iter 2). Single justified lever (row-Y bias) applied and documented.
**Do not start Iteration 4 without explicit approval and an updated failure-pattern review.**

**Next planning options** (not executed):
- **Instrument all-15 dy first**: persist per-target dx/dy (hits + misses) and, ideally,
  pre- vs post-correction benchmark dy, so the row-Y bias transfer/overcorrection question
  can be answered with data instead of miss-only inference.
- The dominant remaining error on the best-row run is **horizontal (X)**, not row — a
  Y-only lever is now low-leverage; consider whether the failure guide points to X/geometry.
- T034: geometry/hitbox verification if preview-on-key looks better than benchmark scoring
  (large negative dx cluster: P→O, L→K, M→N, Z→Shift).
- T033 follow-up: collection/posture stability, given the between-session instability seen
  in key-hit (27%–47%) and in the differing miss-residual dy signs.
- T035 row-Y follow-up only if all-15 dy logging shows a stable, transferable row offset —
  not justified on the miss-only evidence available this cycle.
